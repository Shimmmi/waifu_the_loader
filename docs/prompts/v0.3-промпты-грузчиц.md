## 1. Термины

| Термин | Значение |
| --- | --- |
| Базовый канвас | Корневое окно игры 480×270 «физических единиц» (дальше движок сам растягивает его целым числом раз на экран). Всё, что в таблицах ниже названо «физ. px», — эти единицы |
| s | Множитель масштаба интерфейса: 1, 2 или 3 |
| Режим | `S1` (s = 1), `S2` (s = 2), `S3` (s = 3) |
| Логический экран | Область, в которой верстается интерфейс: `480/s × 270/s`. S1 = 480×270, S2 = 240×135, S3 = 160×90 |
| Логическая единица (лог. px) | Один пиксель логического экрана = `s × s` физ. px. Все размеры UI в тексте и в коде — в лог. px, если не сказано «физ.» |
| `UiRoot` | Единственный корневой `Control` интерфейса: у него `scale = s` и `size = логический экран` |
| Мир | Терминал (разрез здания) и сцена «Погрузка». Рисуется не внутри `UiRoot` и **не масштабируется** этой настройкой |
| Хром | HUD (верхняя полоса), `NavBar` (нижняя панель), и только на вкладке «Терминал» ещё панель инструментов (`toolbar`) |
| Область мира | Прямоугольник внутри базового канваса, где виден мир (между хромом). Выдаётся `UiScale.world_rect(tab_id)` в **физ. px** |
| Область контента | Между HUD и NavBar. В неё вставляются текстовые экраны вкладок |

### 2.1 Требования

| № | Требование (ВСЕ обязательны) |
| --- | --- |
| R1 | В «Меню → Настройки» есть строка «Масштаб UI» с тремя кнопками «1×», «2×», «3×» (спецификация §2.6) |
| R2 | Масштаб применяется мгновенно: без перезагрузки игры, без закрытия текущей вкладки, без сброса прокрутки и выбранных элементов |

| R4 | Режим 1× пиксель-в-пиксель равен состоянию до задачи (IR-3) |
| R5 | Масштабируются: шрифты, HUD, нижняя панель, меню и подменю, кнопки, списки, полосы, иконки интерфейса, панели и модальные окна, баннеры, тосты, подсказки. **Не** масштабируются: мир (терминал, сцена «Погрузка») |
| R6 | Горизонтальных полос прокрутки нет ни на одном режиме |

| R9 | Минимальная цель касания на 2× и 3× ≥ 24 физ. px по меньшей стороне (S2: ≥ 12 лог. px, S3: ≥ 8 лог. px). На 1× ничего не менять |

| R12 | Нативных popup, tooltip и диалогов нет; замены живут внутри `UiRoot` (§2.10) |
| R13 | При смене масштаба открытые модальные окна остаются открытыми и перестраиваются |
| R14 | Переключение масштаба ≤ 100 мс, без загрузки ресурсов, без утечки узлов (число узлов дерева после 20 переключений не растёт) |
| R15 | Языки RU и EN: длинные строки не ломают макет на всех трёх масштабах |
| R16 | В Sim, сохранениях и бэкенде изменений нет |
| R17 | Debug-панели тоже внутри `UiRoot`, но требования R7–R9 на них не распространяются |
| R18 | Все тесты и скриншоты §2.14 приложены и зелёные |

### 2.2 Архитектурное решение (обязательно)

**Масштабируется ровно один узел — `UiRoot`.** У него `scale = Vector2(s, s)` и `size = 480/s × 270/s`. Все элементы интерфейса — его дети. Шрифты и размеры в лог. px не меняются; увеличение происходит от масштаба корня (пиксель-дублирование, `texture_filter = NEAREST`). Столько же полезного места в логическом экране меньше, поэтому экраны адаптируются по таблицам §2.8.

**Почему именно так:** (1) одна точка правды, невозможно «забыть масштабировать» отдельный элемент; (2) пиксель-арт и шрифты остаются чёткими без новых текстур; (3) ввод двигатель пересчитывает сам.

**Запрещённые варианты (делать ТАК НЕЛЬЗЯ):**

| Вариант | Почему запрещён |
| --- | --- |
| Менять `Window.content_scale_factor` или `content_scale_size` | Масштабирует и мир; поведение в режиме viewport непредсказуемо |
| Пересобирать `Theme` с увеличенными шрифтами и StyleBox | Нужны дополнительные текстуры и легко пропустить элемент |
| Помещать интерфейс в `SubViewport` | Ломает передачу событий в мир (камера терминала) |
| Выставлять `scale` у отдельных экранов и виджетов | Двойное масштабирование; рассинхрон макетов |
| Менять размеры шрифтов по масштабу | Сломает пиксельную сетку шрифта; масштаб даёт только `UiRoot` |
| Использовать `PopupMenu`, `OptionButton`, `MenuButton`, `AcceptDialog`, `ConfirmationDialog`, `FileDialog`, `Window`, `tooltip_text` | Они рисуются вне `UiRoot` и не масштабируются |
| Писать `if scale == 2:` в произвольных скриптах | Размазывает логику; разрешено только в `ScreenBase.apply_scale()` и в `Fmt` (§2.7) |
| Дробные масштабы (1.5× и т. п.) | Ломают пиксель-перфект и не входят в задание |

### 2.4 Автозагрузка `UiScale`: код-скелет (реализовать точно так)

```gdscript
# src/core/ui_scale.gd  (autoload name: UiScale)
extends Node

signal scale_changed(new_scale: int)

const BASE_SIZE: Vector2 = Vector2(480, 270)
const ALLOWED: Array[int] = [1, 2, 3]
const MODES: Dictionary = {1: "S1", 2: "S2", 3: "S3"}
const METRICS_PATH: String = "res://data/ui_scale.json"

var scale_factor: int = 1
var mode: String = "S1"
var ui_root: Control = null
var _metrics: Dictionary = {}

func _ready() -> void:
	_metrics = _load_metrics()

func _load_metrics() -> Dictionary:
	var f: FileAccess = FileAccess.open(METRICS_PATH, FileAccess.READ)
	assert(f != null, "ui_scale.json missing")
	var parsed: Variant = JSON.parse_string(f.get_as_text())
	assert(parsed is Dictionary, "ui_scale.json invalid")
	return parsed

func register_root(root: Control) -> void:
	ui_root = root
	_apply_to_root()

func logical_size() -> Vector2:
	return BASE_SIZE / float(scale_factor)

# Все размеры UI — только через эту функцию (лог. px)
func metric(key: String) -> int:
	var table: Dictionary = _metrics["scales"][str(scale_factor)]
	assert(table.has(key), "unknown ui metric: " + key)
	return int(table[key])

func set_scale(value: int, persist: bool = true) -> void:
	var v: int = value
	if not ALLOWED.has(v):
		push_warning("UiScale: invalid scale %d, fallback to 1" % value)
		v = 1
	if v == scale_factor and ui_root != null:
		return
	scale_factor = v
	mode = MODES[v]
	_apply_to_root()
	if persist:
		Settings.set_value("ui_scale", v)   # адаптировать под реальный API Settings
	scale_changed.emit(v)

func _apply_to_root() -> void:
	if ui_root == null:
		return
	ui_root.pivot_offset = Vector2.ZERO
	ui_root.position = Vector2.ZERO
	ui_root.scale = Vector2(scale_factor, scale_factor)
	ui_root.size = logical_size()

# Прямоугольник мира в ФИЗ. px базового канваса
func world_rect(tab_id: String) -> Rect2:
	var top: int = metric("hud_h")
	if tab_id == "terminal":
		top += metric("toolbar_h")
	var bottom: int = metric("nav_h")
	var s: int = scale_factor
	return Rect2(0.0, float(top * s), BASE_SIZE.x, BASE_SIZE.y - float((top + bottom) * s))

# Перевод физ. прямоугольника в логический (для линтера и тестов)
func to_logical(r: Rect2) -> Rect2:
	return Rect2(r.position / float(scale_factor), r.size / float(scale_factor))
```

Правила к коду:

1. Типы только целые (`int`) для масштаба и метрик; дробных масштабов нет.
2. `Settings.set_value` — условное имя: используй тот механизм записи настроек, который уже есть в проекте (звук, язык). Своё хранилище не заводить.
3. В `_apply_to_root()` нельзя менять якоря и прочие свойства `UiRoot`: ровно `pivot_offset`, `position`, `scale`, `size`.
4. `UiRoot._ready()` обязан вызвать `UiScale.register_root(self)` и выставить `mouse_filter = Control.MOUSE_FILTER_IGNORE`, `texture_filter = CanvasItem.TEXTURE_FILTER_NEAREST`, `focus_mode = Control.FOCUS_NONE`, `clip_contents = false`.
5. При старте игры до построения всех экранов: `UiScale.set_scale(Settings.get_value("ui_scale", 1), false)`.

### 2.5 Метрики `data/ui_scale.json`

Формат файла: `{"scales": {"1": {...}, "2": {...}, "3": {...}}}`. Ключи и значения (лог. px, если не сказано иначе):

| Ключ | S1 | S2 | S3 | Пояснение |
| --- | --- | --- | --- | --- |
| `hud_h` | 24 | 16 | 12 | Высота HUD |
| `nav_h` | 24 | 16 | 14 | Высота нижней панели |
| `toolbar_h` | 38 | 16 | 0 | Панель инструментов «Терминала» (кнопки + строка «Смена: …») |
| `btn_h` | 24 | 14 | 10 | Высота обычной кнопки |
| `row_h` | 24 | 16 | 16 | Высота строки списка |
| `pad` | 4 | 2 | 2 | Внутренний отступ панелей |
| `gap` | 4 | 2 | 1 | Разрыв между элементами (`separation`) |
| `bar_h` | 6 | 4 | 3 | Высота полосы прогресса |
| `scroll_w` | 8 | 6 | 4 | Ширина полосы прокрутки |
| `panel_margin` | 6 | 3 | 2 | Отступ модальных окон от края экрана |
| `portrait_px` | 96 | 48 | 48 | Размер портрета в карточке (арт 48×48: на S1 показывается ×2, на S2/S3 ×1) |
| `max_name_chars` | 18 | 11 | 8 | Максимум символов имени до многоточия |
| `rush_btn_w` | 46 | 36 | 12 | Ширина кнопки «Рывок» (S3 — иконка) |
| `touch_min` | — | 12 | 8 | Минимум цели касания (R9); на S1 не проверяется |
| scale\_btn\_w | 32 | 28 | 22 | Ширина кнопки в строке «Масштаб UI» (§2.6) |

- Иконки: размеры не меняются по режимам: маленькие иконки навигации 12×12, иконки класса/расы/головки 16×16 (они масштабируются вместе с `UiRoot`).

| № | Правило |

**Код-скелеты (создать точно так):**

```gdscript
# src/ui/screen_base.gd
class_name ScreenBase
extends Control

func _ready() -> void:
	mouse_filter = Control.MOUSE_FILTER_IGNORE
	UiScale.scale_changed.connect(_on_scale_changed)
	apply_scale(UiScale.scale_factor)

func _on_scale_changed(new_scale: int) -> void:
	apply_scale(new_scale)

# Переопределяется в наследниках. Здесь (и только здесь) допустимо читать UiScale.mode
func apply_scale(_s: int) -> void:
	pass
```

```gdscript
# src/ui/widgets/scale_visibility.gd
class_name ScaleVisibility
extends Node

@export var show_s1: bool = true
@export var show_s2: bool = true
@export var show_s3: bool = true

func _ready() -> void:
	UiScale.scale_changed.connect(_apply)
	_apply(UiScale.scale_factor)

func _apply(s: int) -> void:
	var target: CanvasItem = get_parent() as CanvasItem
	if target == null:
		return
	target.visible = (s == 1 and show_s1) or (s == 2 and show_s2) or (s == 3 and show_s3)
```

Узел с `ScaleVisibility` в родителях нельзя показывать/скрывать другим кодом.

```gdscript
# добавить в src/core/ui_scale.gd
func style_scroll(sc: ScrollContainer) -> void:
	sc.horizontal_scroll_mode = ScrollContainer.SCROLL_MODE_DISABLED
	sc.get_v_scroll_bar().custom_minimum_size.x = float(metric("scroll_w"))
```

`Fmt.name(s: String, max_chars: int) -> String`: если `s.length() <= max_chars` вернуть `s`; иначе `s.substr(0, max_chars - 1) + "…"`.

### 2.9 Мировые виды и область мира

- В `Main` создаётся узел **`WorldClip`** (`Control`, `clip_contents = true`, `mouse_filter = IGNORE`), он лежит в `World` (вне `UiRoot`, не масштабируется). Терминал и сцена «Погрузка» — его дети.
- При смене вкладки и при `UiScale.scale_changed` `Main` выставляет `WorldClip.position` и `WorldClip.size` из `UiScale.world_rect(tab_id)` (тексты вкладок без мира скрывают `WorldClip`).
- Миры считают свой размер из `WorldClip.size`, а не из констант 480/270. Начало координат мира — левый верхний угол `WorldClip`.
- Ввод в мире: события, пришедшие вне `WorldClip`, не обрабатываются; проверка `get_global_rect().has_point(event.position)`.
- Камера терминала (v0.2 WP-E) использует `WorldClip.size` как размер вьюпорта.

| `tooltip_text` | `UiTooltip` | Один экземпляр в `Overlays`. `UiTooltip.attach(control, text_or_key)`. Показ: мышь — наведение 400 мс; касание — долгое нажатие 500 мс. Скрыть при любом нажатии. Позиция над элементом, зажата в границы логического экрана |
| `PopupMenu`, `MenuButton`, `OptionButton` | `UiSelect` | Кнопка, которая открывает в `Overlays` панель со списком кнопок. Сигнал `item_selected(index: int)`. Закрытие тапом вне |
| `ConfirmationDialog`, `AcceptDialog` | `UiConfirm` | `UiConfirm.ask(title_key, body_key, ok_key, cancel_key)`; результат сигналом `answered(accepted: bool)`. Затемнённая подложка (STOP) |
| `FileDialog`, `Window`, `popup*()` | — | Не использовать |

Встроенные подсказки движка отключить: у всех Control `tooltip_text = ""`.

### 2.11 Ввод

- `UiRoot`, `Content`, `Overlays` и экраны (`ScreenBase`) — `mouse_filter = IGNORE`. `Hud` и `NavBar` — `Panel` с `STOP`. Интерактивные панели внутри экранов — `STOP`. Затемнённые подложки модальных окон — `STOP`, пока окно открыто.
- Пустая область мира (вкладки «Терминал», «Погрузка») не должна содержать Control с `STOP`: события доходят до мира.
- Новых горячих клавиш нет. Существующие работают как раньше.
- Горизонтальный свайп листает `CardPager` и подразделы «Мира». Порог 12 лог. px, при преобладании горизонтальной составляющей.
- Эмуляция касаний из мыши и порог перетаскивания движка не менять.

### 2.12 Сохранение настроек

- Ключ `ui_scale` (целое 1, 2 или 3) пишется в тот же файл локальных настроек, где лежат язык и звук. В игровое сохранение, облако и бэкенд не пишется.
- Значение вне {1, 2, 3} или отсутствие ключа → 1 (для неверного значения — `push_warning`).
- Читается до построения экранов (§2.4, правило 5).

### 2.13 Производительность

- `set_scale()` + два кадра ≤ 100 мс (замерять `Time.get_ticks_usec()`).
- 20 переключений подряд: `get_tree().get_node_count()` после последнего равен значению до первого (утечек нет).
- FPS на 1× не падает относительно состояния до задачи; на 2× и 3× — не ниже 55 FPS на эталонном ноутбуке.
- Масштабирование `UiRoot` не создаёт новых текстур и ресурсов.
